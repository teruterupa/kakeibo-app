# カレンダー表示・ボタン大型化 設計書

## 目的

`docs/superpowers/specs/2026-08-10-transaction-list-and-summary-design.md`で実装した一覧・集計機能（`/transactions`）を土台に、以下2点を追加する。

1. カレンダー表示で「いつ・いくらお金が動いたか」を一目で見えるようにする（収入は青字、支出は赤字）。
2. トップページの「一覧・集計を見る」を、押しやすい大きめのボタンに変更する。

## 画面構成

### カレンダーページ（新規: `/calendar`）

- 新しい独立ページとして追加する（トップページや`/transactions`には統合しない）。
- `/transactions`と同じ`month`クエリパラメータ（`YYYY-MM`形式）で月を切り替える。前月・翌月ボタンを`/transactions`と同様のUIで用意する。
- カレンダーは7列（日〜土）のグリッドで、その月の日数分のマスを表示する。
- 各日のマスには以下を表示する。
  - 日付（数字）
  - その日の収入合計（該当する取引があれば、青字で`+¥300`のように表示）
  - その日の支出合計（該当する取引があれば、赤字で`-¥1,200`のように表示）
  - 収入・支出どちらもない日は金額を表示しない
- 日付のマスをタップ（クリック）すると`/transactions?month=YYYY-MM&date=YYYY-MM-DD`へ遷移する。

### 一覧ページの日付絞り込み対応（`/transactions`拡張）

- `date`クエリパラメータ（`YYYY-MM-DD`形式）が付与されている場合、取引一覧をその日だけに絞り込んで表示する。
  - データ取得自体は既存どおり月単位のまま行い、絞り込みは取得後の表示側で行う（新規のDBクエリは追加しない）。
- 絞り込み時は見出しを「◯月◯日の取引」に変更し、「月全体を表示」リンクで絞り込み解除（`date`パラメータなしの同ページ）に戻れるようにする。
- 月別集計（合計・カテゴリ別内訳）は`date`の有無に関わらず常に月全体のまま表示する（日ごとの再集計はしない）。
- 編集・削除機能は既存のまま変更しない。

### トップページのボタン大型化

- 現在の「一覧・集計を見る」（`app/page.tsx`、下線付きの小さいテキストリンク）を、`w-full`かつパディングを増やした押しやすいボタン風の見た目に変更する。
- 新設する「カレンダーで見る」（`/calendar`へのリンク）も同じボタンスタイルで隣接して追加する。
- 対象はこの1箇所のみ。月切り替えの前月・翌月ボタンや、一覧の行内の編集・削除ボタンは今回のスコープに含めない。

## データ取得方式

- カレンダーページは既存の`getTransactionsForMonth(month)`（`lib/transactions.ts`）をそのまま利用し、取得結果を日付ごとにグルーピングして各日の収入合計・支出合計を計算する（新規のSupabaseクエリ関数は不要）。
- 日付ごとの集計ロジックは、`lib/transactions.ts`に新しい関数（例: `groupTransactionsByDay`）として追加し、カレンダーページ側はその結果を描画に使うだけにする。

## エラー処理

- `/calendar`でのデータ取得に失敗した場合は、`/transactions`と同じパターンでエラーメッセージを表示し、カレンダー本体（グリッド）は描画しない。
- `/transactions`の`date`パラメータがその月に存在しない日付・不正な形式などの場合は、絞り込みを行わず月全体の一覧を表示する（エラー扱いにはしない）。

## テスト方針

- 既存機能と同様、自動テストは追加せず手動確認のみとする。
- 実装完了後、`npm run lint`と`npm run build`が通ることを確認する。
- 手動確認項目:
  - カレンダーページの月切り替え（前月・翌月）
  - 日ごとの色分け表示（収入のみ／支出のみ／両方／どちらもない日）
  - 日付タップで`/transactions`のその日絞り込み表示に遷移すること
  - 「月全体を表示」で絞り込み解除できること
  - 絞り込み表示中でも編集・削除が正しく動作すること
  - トップページの2つのボタン（一覧・集計／カレンダー）の見た目とタップ操作

## スコープ外

- 週表示・年表示
- グラフによる可視化
- カレンダー上でのドラッグ操作・複数日選択
- 日別集計を独立したカードなどで別表示すること
- 認証（NextAuth.js導入）、自動テスト整備
