# 収支登録フォーム 設計書

日付: 2026-08-09

## 目的

家計簿アプリの最初の機能として、支出・収入を1件ずつ登録できるフォームを作る。登録したデータはSupabase（クラウドDB）に保存する。一覧表示・集計・認証は今回のスコープ外とし、別途今後の機能として設計する。

## データモデル

Supabase（PostgreSQL）に`transactions`テーブルを作成する。

| カラム名 | 型 | 内容 |
|---|---|---|
| `id` | uuid（default: `gen_random_uuid()`） | 主キー |
| `date` | date | 取引の日付 |
| `type` | text（`income` または `expense`） | 収入か支出か |
| `category` | text | カテゴリ（下記の固定リストから） |
| `amount` | integer | 金額（円、常に正の数） |
| `memo` | text（nullable） | メモ |
| `created_at` | timestamptz（default: `now()`） | 登録日時 |

### カテゴリ（固定リスト）

- 支出用：食費 / 日用品 / 交通費 / 娯楽 / 光熱費 / 住居 / その他
- 収入用：給与 / 副業 / その他

収入・支出それぞれで選べるカテゴリを分ける（画面側で`type`の選択に応じてプルダウンの選択肢を切り替える）。

## 画面構成

- `app/page.tsx`（トップページ）を、現在の雛形サンプル画面から入力フォームに置き換える。
- フォーム項目：
  - 収入 / 支出 の切り替え（ボタンまたはタブ）
  - 日付（デフォルトは当日）
  - 金額（数値入力）
  - カテゴリ（選択中の収入/支出に応じて選択肢が切り替わるプルダウン）
  - メモ（任意入力）
  - 「登録する」ボタン
- 登録成功時：フォームをリセットし、「登録しました」という簡易メッセージを表示する。一覧表示は行わない（スコープ外）。

## データ保存方式

Next.js App RouterのServer Actionsを使う。

- フォームの`action`にServer Action（`"use server"`）を直接指定し、送信時にサーバー側でSupabaseへの保存処理を行う。
- クライアント側でのfetch呼び出しやAPI Routeの作成は不要。
- Supabaseへの接続には、サーバー側で`.env.local`の`NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`を使ったクライアントを利用する。

選定理由：コード量が少なく、Next.js App Routerで現在最も標準的とされる書き方のため。クライアント側から直接Supabaseへ保存する方式（コード量がやや増える）、専用API Routeを作る方式（この規模では過剰）と比較して採用した。

## セキュリティ・入力チェック

- **RLS（Row Level Security）**: 現段階では認証機能が無いため、制限を設けない（全許可）。**認証（NextAuth.js）を導入する際に、RLSを見直すことが必須**。この注意点はCLAUDE.mdにも記載する。
- **入力チェック**（Server Action内で実施）:
  - 金額が未入力・0以下・数値以外の場合はエラーとし、保存しない
  - 日付・カテゴリが未選択の場合はエラーとし、保存しない

## Supabaseプロジェクトについて

Supabaseプロジェクトはまだ作成されていない。実装後、ユーザー自身がsupabase.comでプロジェクトを作成し、`.env.local`にURLとAPIキーを設定する必要がある（アカウント作成はユーザー側の手作業）。実装計画にセットアップ手順を含める。

## テスト方針

自動テストの仕組み（Jest等）は今回導入しない。`npm run dev`でローカル起動し、収入・支出それぞれを実際に登録してSupabase側にデータが反映されることを手動で確認する。
